# ADR 004: Editing generated shadcn-svelte UI primitives

- **Status:** Accepted
- **Date:** 2026-06-22
- **Owner:** Winston (Architect)
- **Source:** Epic 1 retrospective action item AI-3

## Context

The `src/lib/components/ui/**` primitives are generated by the shadcn-svelte CLI
(story 1-1). We deliberately edit some of them, and **those edits are silently lost
the next time the CLI regenerates the component**. The Epic 1 retro flagged this twice.
Two concrete edits live in `src/lib/components/ui/button/button.svelte`:

1. **A lint exception** — the generated `<a href>` branch trips
   `svelte/no-navigation-without-resolve`, so an inline
   `<!-- eslint-disable svelte/no-navigation-without-resolve -->` /
   `<!-- eslint-enable -->` pair was added by hand. A regen drops it, and lint then fails.
2. **The brand size-variant contract** — the `buttonVariants` `size` block was edited to
   the passanger brand sizes (`sm` 40px / `default` 44px / `lg` 52px / `icon` 44², radius
   `rounded-md`), replacing the stock shadcn sizes. A regen reverts these to stock.

These differ in kind: (1) is a _lint-config_ concern that can move out of the file;
(2) is _intrinsic content_ of the generated file that cannot.

## Decision

**Split the two by where the fix can live.**

1. **Lint exception → eslint config (regen-safe).** Scope
   `svelte/no-navigation-without-resolve` **off** for `src/lib/components/ui/**/*.svelte`
   in `eslint.config.js` (mirrors the existing dexie-import scoped block). The generic UI
   primitive passes `href` through as an opaque prop; the _caller_ owns resolving the path,
   so the rule is correctly disabled for the primitive layer, not app code. The inline
   `eslint-disable`/`eslint-enable` comments in `button.svelte` are then redundant and are
   **removed** — a regen no longer needs a hand-edit to keep lint green.

2. **Intrinsic edits → documented regen checklist (cannot move to config).** The brand
   size-variant block stays in `button.svelte`; it is part of the component's content. We
   accept the regen-loss risk and record the canonical edits here so a regen can be repaired
   deterministically. **After any `shadcn-svelte` regen of `button.svelte`, re-apply:**
   - `size.default`: `h-11` (44px), `rounded-md`, `px-4`
   - `size.sm`: `h-10` (40px), `rounded-md`, `px-3.5`
   - `size.lg`: `h-13` (52px), `rounded-md`, `px-5`
   - `size.icon`: `size-11` (44²), `rounded-md`
   - keep the `// passanger brand contract (DESIGN.md / UX-DR1)` comment as the marker
     The component test (and the `docs/primitive-migration-pattern.md` size table) encode the
     same contract, so a reverted regen surfaces as a failing/inconsistent size.

We did **not** fork the primitives out of the generated tree, nor pin/automate the CLI —
both are heavier than the residual risk warrants for a single edited primitive.

## Consequences

- **Positive:** The lint exception is now regen-proof and lives where lint config belongs.
  `button.svelte` has one fewer hand-edit; a clean regen passes lint unchanged.
- **Positive:** The remaining regen-loss risk is small, explicit, and has a deterministic
  repair recipe — no longer tribal knowledge.
- **Negative / residual:** If `button.svelte` is regenerated, the size variants still need
  manual re-application from the checklist above. Mitigated by the component test + the
  migration-pattern size table failing loudly on drift.
- **Scope:** Today only `button.svelte` carries intrinsic edits. Add a checklist entry here
  if a future primitive is edited (e.g. `sonner.svelte` icon trimming).
