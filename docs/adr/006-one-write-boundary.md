# ADR-006 — One write boundary: repo-grade invariants for every writer

- **Status:** **Accepted** (architecture sign-off — discharges **PREP-8.1**; hard gate before Story 8.2 dev)
- **Date:** 2026-07-02
- **Deciders:** Winston (Architect), Csabagura (PO/Project Lead)
- **Amends (scoped):** **AD-DA-2** (all mutations behind repositories) and **AD-DA-4** (validation lives in the repository validators) — extends both from "the UI create/update path" to **every** writer (UI, CSV import, backup restore). Refines **AD-DA-3** (timeline integrity owned by `fuelLogTimeline`) and extends **AD-7** (reversible-delete generation guard) to the restore event. **No schema change** — strictly logic/contract.
- **Context source:** `logic-audit-2026-07-02.md` (H14/S12, H3, H6, H17a/b/c, H4, S13–S17, S33; Part 3 §1 "invariant ownership split by accident of history"; Part 4 consolidation); `sprint-change-proposal-2026-07-02.md` §3.2(a); Story 8.2 (`epics.md`).
- **Related:** ADR-005 (v5 fill-quality flags + strict-anchor rule D1), `deferred-work.md`, Epic-4/6 retros (AD-7 generation guard). Baseline verified at `main @ deeac5d` (post Story 8-1).

## Context

The audit's **#1 systemic theme** is that data invariants are enforced for **one** writer and silently bypassed by the others: "every invariant lives at the write boundary that all writers share" is stated as an aspiration but is not how the code is built. Three second writers exist today, each re-verified at HEAD:

1. **The UI edit path is a TOCTOU (H14, subsumes S12).** `FuelEntryForm.svelte` loads the vehicle's timeline into a `$state` snapshot at mount (`:440-449`), computes the update plan **in the component** from that snapshot on save (`buildFuelLogUpdatePlan(...)`, `:640`), and hands the finished plan to `updateFuelLogsAtomic`, which applies the patches inside a transaction **without ever re-reading** (`fuelLogs.ts:160-197`). A concurrent write between mount and save — a second tab, or the documented dual-mounted page+CaptureSheet — commits consumption computed against a stale predecessor. The cross-tab variant is real: `history/+page.svelte` bumps `fuelEditTimelineVersion` only on a **same-tab** delete (`:355`), so tab A's neighbor edit is invisible to tab B's open form (S12). This is the exact inverse of the **correct** pattern already used by `deleteFuelLog` (`fuelLogs.ts:199-258`) and `restoreFuelLog` (`:265-331`), which fresh-read + build-plan + apply **inside one `db.transaction('rw')`** with in-transaction re-validation.

2. **Import commit bypasses the repository entirely (H3, H6).** `importCommit.ts` creates vehicles **outside and before** the rows transaction (`:46-66`, write at `:56`; the `db.transaction('rw', …)` at `:153` spans only `fuelLogs` + `expenses`), so a mid-commit failure orphans the vehicles with zero cleanup and a Retry — whose assignments are never rewritten from `new` to `existing` — re-creates them as duplicates, then throws a bogus `MAX_VEHICLES` on the third try. The failure screen says "your data hasn't changed" — false. Rows are written with raw `db.fuelLogs.add(row as any)` / `db.expenses.add(row as any)` (`:170`, `:186`), trusting non-null assertions and **never** calling `validateNewFuelLog`. Because the three parsers detect fuel unit and distance unit **independently** (`importParseFuelly.ts:57-58`; aCar & Drivvo likewise) and `importValidation.ts` never inspects units at all, a UK-style litres+miles export lands invalid **`L`+`mi`** rows — the one invariant the repo validator enforces (`fuelLogs.ts:22-28`) and the import path cannot. Those rows read ~1.6× wrong on per-entry surfaces while Home self-heals, and freeze uneditable the moment any later edit re-trips `validatePartialFuelLog`.

3. **The backup boundary is asymmetric with the write boundary (H17a/b/c).** `parseBackup`'s `isValid*` shape-checks (`utils/backup.ts:49-105`) admit what the repositories reject: no unit↔distanceUnit pairing, `typeof === 'number'` passing `NaN`/`±Infinity`/negatives/zero (no `Number.isFinite`, no sign check), empty strings, no `vehicleId` referential integrity (orphans restore unreachable), no `MAX_VEHICLES` cap (restore `bulkPut` bypasses `saveVehicle`'s count gate). Inversely, backup **does** gate the v5 booleans (`:76-77`) while the fuel repo validators **don't** (S16) — drift in both directions from having two validator families. Export never validates (`db/backup.ts:27-47`): a single legacy `NaN` field → `JSON.stringify` → `null` → the whole backup is unrestorable, discovered the day it's needed (H17b). And restore does not bump the local data generation (`tabSync.ts` `notifyTabsRestored` posts `'restore'` with no `localDataGeneration += 1`; the receiving tab's layout `'restore'` branch returns before `dataRevision++`), so a pending cross-tab Undo's guard (`history:436`) sees both signals unchanged, passes, and writes a **pre-restore** snapshot into the freshly restored DB (H17c).

Two more findings share the same root and are folded here:

4. **The below-previous odometer poison (H4)** is a write-boundary gap masquerading as an engine bug. `recalculateSortedFuelLogs` (`fuelLogTimeline.ts:47-86`) selects the span anchor **purely** on `isPartialFill` (the `else` at `:79-84` re-anchors on **every** full fill), fully decoupled from whether that fill's own span came out positive. A below-previous full fill reports an honest `0` for itself (`calculations.ts:54`, `distance <= 0 → 0`) but **still overwrites the anchor to its bogus-low odometer**, so the next full fill measures a 45,000-km span and collapses lifetime averages. Create-mode permits it with only an amber warning (`FuelEntryForm.svelte:596-600`) on the false premise that "the typo row itself computes 0"; edit-mode then hard-forbids odometer ≤ predecessor (`:601-610`), trapping the row uncorrectable — the only repair is delete + re-log.

5. **The four repositories duplicate ~200 lines of write-skeleton that has drifted (S13–S17, S33).** Three validators call `.trim()` on possibly-non-string input **outside** `try` (`vehicles.ts:10-12`, `expenses.ts:13`, `serviceReminders.ts:15`), throwing a `TypeError` **across** the `Result` boundary; `deleteFuelLog` omits quota mapping though it writes neighbor patches (`fuelLogs.ts:246-257`, S15); `updateServiceReminder` can clear **both** intervals (`serviceReminders.ts:37-75` lacks the "≥1 interval" invariant → Dexie deletes the undefined keys → a permanently inert reminder, S13); delete-nonexistent is inconsistent and `serviceReminders`/`vehicles` fire a spurious `notifyDataChanged` on a no-op delete, bumping the generation and killing a pending Undo (S17); sentinel `Error('CODE:detail')` prefixes leak into user-facing `AppError.message` where no decoder matches (`fuelLogs.ts:179,235`, S33); the v5-flag boolean gate is missing from the repo validators (S16).

**None of this is a schema problem.** It is a _boundary_ problem: the same row can be accepted by one writer and rejected by another. This ADR is the required architecture sign-off before Story 8.2 leaves `ready-for-dev`. (Story 8-1 already closed the point-leaks that were one-liners — `currency` now rides in `buildFuelLogUpdatePlan` (H1), `finiteOr0` coerces cost at the import commit boundary (H8), the fuel validators enforce `odometer > 0` and the L↔km/gal↔mi pair (FIX #3); those are **done** and this ADR does not re-decide them. It makes them **systemic**.)

## Decision

**Establish one write boundary.** Every writer — UI create/update, import commit, backup restore — passes through **repository-grade validation** and **in-transaction timeline planning**. No writer may persist a row another writer would reject. The six decisions below are logic/contract only; no field, index, table, migration, or `DB_VERSION` changes.

### AD-WB-1 — Create/update fuel-log plans are built **inside** the repository transaction (amends AD-DA-3; closes H14, subsumes S12)

Add a repo-owned **`updateFuelLogWithTimeline`** (and align the create path) that, inside one `db.transaction('rw', db.fuelLogs, …)`, **fresh-reads** the vehicle's timeline, calls `buildFuelLogUpdatePlan`, and applies the patches — the exact shape of `deleteFuelLog`/`restoreFuelLog` today. The UI stops computing plans from mount-time snapshots and calls the repo with the intended row only; the component keeps its snapshot solely for pre-submit UX (odometer warnings), never as the source of the persisted plan. The unconsumed, timeline-blind **`updateFuelLog` single-row export is removed** (`fuelLogs.ts:144-158`) — it is a standing bypass footgun with zero production callers. `updateFuelLogsAtomic`'s "apply a pre-built plan" role either disappears into `updateFuelLogWithTimeline` or is retained only as an in-transaction internal. Cross-tab staleness (S12) dissolves because the plan is always computed from the DB state at commit, not from any tab's snapshot.

### AD-WB-2 — One shared row-validator module is the single source of row invariants (amends AD-DA-4; closes H3-validation, H17a, S16)

Extract the row-shape invariants into **one module** (e.g. `src/lib/db/validators/` or `src/lib/utils/rowValidation.ts`, sited to respect Dexie-isolation) exporting pure `typeof`-guarded validators: **unit↔distanceUnit pairing** (L↔km, gal↔mi), **finiteness** (`Number.isFinite`), **positivity/sign** (odometer > 0, quantity > 0, cost ≥ 0), **non-empty strings** (`.trim() !== ''`), **v5 boolean-flag gates** (`isPartialFill`/`precededByMissedFill` are `undefined | boolean`), **`vehicleId` referential integrity**, and **`MAX_VEHICLES`**. It is consumed by **(a)** the repository `validateNew*/Partial*`, **(b)** `importCommit` per row, and **(c)** `parseBackup`'s `isValid*`. This ends the two-direction drift (pairing was repo-only; the v5 boolean gate was parser-only). The fuel repo's existing typeof-guarded validators (`fuelLogs.ts:9-104`) are the template; the other three repos and the two bypassing writers adopt it.

### AD-WB-3 — Import commit is **transactional and validated** (amends AD-DA-2; closes H3, H6)

Vehicles are created **inside** the commit transaction (or their assignments reconciled from `new` to `existing` only after a fully successful commit) so a failed commit cannot orphan or retry-duplicate vehicles, and the "your data hasn't changed" copy becomes truthful. Every fuel and expense row is validated with the **shared validators** (AD-WB-2) before `add` — no `L`+`mi` rows, no zero/negative odometer or quantity slipping past. The three redundant `MAX_VEHICLES` read-then-write checks collapse toward the transactional one. **Scope fence:** this decision covers _validation + transactionality only_. Import **behaviour** changes — duplicate detection (H7), bulk-accept-warnings + honest skip accounting (H9), `normalizeDecimal` (H20), BOM-before-detect (S3), the generic-CSV dead-end (S4), `±Infinity` in `importValidation` (which uses `isNaN`, catching `NaN` but not `±Infinity`) — are **Story 8.3**, not here.

### AD-WB-4 — The backup boundary is **symmetric** with the write boundary (closes H17a/b/c; extends AD-7)

**(a)** `parseBackup` validates rows with the **shared validators** (AD-WB-2), including `vehicleId` referential integrity across the file and the `MAX_VEHICLES` cap on the vehicles array — a hand-edited or legacy backup can no longer seed invariant-breaking rows. **(b)** **Export validates rows before serialising** (`db/backup.ts`): a corrupt row is surfaced at export time (a truthful `err`) rather than silently `null`-ified by `JSON.stringify` into an unrestorable backup. **(c)** A **restore bumps the local data generation** (`notifyDataChanged` semantics on the restore path, extending AD-7's guard to this event) so a pending Undo in another tab can never write pre-restore data into the restored DB. The `schemaVersion` floor (`>= 4`, reject `> DB_VERSION`) and the additive forward-compat coercion from ADR-005 are **unchanged**.

### AD-WB-5 — The anchor-trust rule (closes H4) — _the domain decision_

**Anchor selection is coupled to span trust.** In `recalculateSortedFuelLogs`, a full fill becomes the next span's anchor **only when its odometer is strictly greater than the current anchor's** (a positive span). A full fill whose odometer does **not** exceed the current anchor — an odometer **regression**, the below-previous anomaly — is **untrusted**: it reports an honest `0` and **does not overwrite the anchor**, so the following span is measured from the last trusted reading and cannot be poisoned. Consistent with ADR-005's strict-anchor doctrine (D1: an untrusted reading contributes `0` and never blends), the untrusted fill's litres are **not carried forward** — importing a known-corrupt endpoint's fuel into a trusted span's numerator would re-introduce a smaller copy of the same poison; under-counting one top-up is bounded and honest, over-attributing is not. The legitimate **first-ever anchor** (no prior anchor) is unaffected — it anchors with a `0` self-reading exactly as today; distance-unit changes continue to break the span (existing behaviour).

The **create-permits / edit-forbids asymmetry is resolved**: with the engine now robust, create-mode's non-blocking amber warning is genuinely safe (integrity no longer depends on the user heeding it), and the **edit path is relaxed so the anomalous row is correctable in place** — an edit may set an odometer that resolves a regression the row itself introduced, rather than forcing delete + re-log. Exact validation-relaxation shape is the story's, with a regression test proving a below-previous typo is correctable without deletion.

**Stored-span-distance is explicitly out of scope (design-of-record note).** Audit Part 3 §2 recommends storing `spanDistance` (or the anchor odometer) per row to delete the inverse-arithmetic class (`analytics.ts:98-100` re-derives distance from stored `calculatedConsumption`). That is a **schema change** → a **future additive migration**, not this ADR (which is fenced to no schema change), mirroring how ADR-005 recorded `ServiceReminder.distanceUnit` as design-of-record then deferred it. For now, span distance is computed **in-transaction** by the engine and the analytics inverse-derivation remains a tracked defect. Consequently, **Story 8.4's `costOfOwnership.ts` decision** (which `epics.md:675` defers to "the stored-span-distance decision from ADR-006") is: `costOfOwnership` stays **deleted**; should a real consumer bring it back (FR-19), it must consume **engine-computed** span distance and must **not** assume a stored `spanDistance` field exists.

### AD-WB-6 — One repository write-skeleton (closes S13–S17, S33; Part 4 consolidation)

The four repositories share **one** write-skeleton — a `runWrite(validator, op)` wrapper plus a single **sentinel encode/decode** pair — so the drift is fixed structurally, not per-repo: **typeof-guarded** validators run inside the guarded path (no `.trim()` `TypeError` across the `Result` boundary, S14); **quota mapping on every writing op**, including `deleteFuelLog` (S15); **consistent delete-nonexistent semantics** with **no spurious `notifyDataChanged`** on a no-op delete (S17); **v5-flag boolean gates** in the repo validators (via AD-WB-2, S16); a **sentinel codec** that strips the `CODE:` prefix from user-facing messages (S33); and **`updateServiceReminder` refusing to clear both intervals** (S13). This is the fix for the copy-paste-drift defect class — consolidation is the correctness fix, not cosmetics.

## Files in scope (Story 8.2)

Repositories: `src/lib/db/repositories/fuelLogs.ts`, `vehicles.ts`, `expenses.ts`, `serviceReminders.ts` · new shared validator + write-skeleton modules (Dexie-isolation-respecting) · `src/lib/utils/fuelLogTimeline.ts` (+ `calculations.ts` if the anchor-trust check lands there) · `src/lib/utils/importCommit.ts` · `src/lib/utils/backup.ts` (parse validators) · `src/lib/db/backup.ts` (export validation) · `src/lib/utils/tabSync.ts` + restore call-site (generation bump on restore) · `src/lib/components/FuelEntryForm.svelte` (stop computing the persisted plan; relax edit odometer bound for the anomalous row) · `src/routes/history/+page.svelte` (open-edit staleness dissolves with AD-WB-1). Co-located `*.test.ts` throughout. **Exact file:line anchors and change shapes are the create-story deliverable.**

## Testing mandates

- **AD-WB-1:** a **concurrent-write edit test** — mutate the timeline in the DB after the form's mount snapshot, then save, and assert neighbor consumptions are recomputed against the **committed** state, not the snapshot (this test must fail against today's `updateFuelLogsAtomic`).
- **AD-WB-2/3:** an import of an `L`+`mi` (litres+miles) row is **rejected/flagged** at commit, not written; a mid-commit failure leaves **zero** orphan vehicles and a Retry creates **no** duplicates (`fake-indexeddb`, forced-throw in the transaction).
- **AD-WB-4:** a **hand-edited-backup rejection suite** (NaN/Infinity/negative numerics, empty strings, unpaired units, dangling `vehicleId`, `> MAX_VEHICLES`); an export of a row carrying a legacy `NaN` returns `err` instead of producing an unrestorable file; a restore bumps the generation such that a pre-restore Undo guard **refuses**.
- **AD-WB-5:** the H4 scenario (full → below-previous full → full) yields **no** poisoned span and **no** inverted `getFuelEntryDistance`; the first-ever anchor and unit-break behaviours are unchanged; a below-previous row is **correctable via edit** without deletion.
- **AD-WB-6:** non-string input to each validator returns `err('VALIDATION_ERROR', …)` (never throws); `deleteFuelLog` maps quota; a no-op delete does **not** bump the generation; `updateServiceReminder` cannot clear both intervals; no `CODE:` prefix reaches an `AppError.message`.
- Standing gates: `check` / `lint` / `test` / `test:a11y`; **`test:artifacts` ≤ 255 KB** (PREP-4.1 — measure per-PR, raise only on real breach; not expected — logic, not payload); CSP `connect-src 'none'` byte-unchanged (NFR-1).

## Fences (hard)

- **No schema change** — no field/table/index add/remove/rename, no migration, `DB_VERSION` stays **5**. Stored-span-distance and any reminder-schema work are **future** migrations (the latter is ADR-007/Story 8.5).
- **No network / CSP / service-worker / privacy-contract change.** The write boundary runs fully offline.
- **`Result<T>` discipline** (no throw across the repository boundary) and **Dexie isolation** (`import 'dexie'` only under `src/lib/db/**`) hold — the shared modules are sited to respect the ESLint restriction.
- **No import _behaviour_ change** beyond validation + transactionality — dedupe (H7), bulk-accept (H9), `normalizeDecimal` (H20), `±Infinity` in `importValidation`, generic-CSV are **Story 8.3**.
- **No insight/metrics change** (Story 8.4) and **no reminder-model change** (Story 8.5); the analytics inverse-arithmetic defect stays tracked, not fixed here.

## Consequences

**Positive:** the "second-writer" defect class is closed structurally — a row valid for one writer is valid for all; the TOCTOU and cross-tab-staleness class disappears because plans are computed at commit; backups become trustworthy in both directions; the below-previous poison is contained _and_ correctable; ~200 lines of drifted write-skeleton collapse to one, taking S13–S17/S33 with them. The write path gains a single, testable contract that Stories 8.3–8.6 build on.

**Negative / risk:** `updateFuelLogWithTimeline` is the highest-risk edit — moving plan-building into the transaction must preserve the exact create/edit consumption results (regression-tested against the current outputs, not just "green"). The shared-validator extraction touches all four repos at once; the mitigation is that the fuel repo's validators already encode the target semantics, so it is a _lift-and-share_, not a _redesign_. The anchor-trust change is the subtlest correctness surface and carries the bulk of the engine unit tests. Review-uniformity discipline (independent 3-layer review, AI-5.1) explicitly applies — a "structural" story is exactly the kind the discipline must not skip.
